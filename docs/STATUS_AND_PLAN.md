## 3. 설계 문서에 없어 구현하면서 정한 것

설계 문서의 12장(열린 문제)이 비어 있어 아래는 구현 중에 정했다. 주최 측 답변에 따라 바꿀 수 있다.

| 결정 | 이유 |
|---|---|
| **보고 위치**: CSS 은닉은 "숨김이 걸린 요소"(글자에 가장 가까운 것), 글자 위장은 "글자를 직접 가진 요소" | 공모전 예시(`span.visually-hidden`, `td.title > a`)와 맞고, 한 요소에 문자열이 여럿이어도 1건이 된다 |
| 숨김이 여러 겹이면 안쪽 요소만 보고 | 같은 문구를 두 위치로 보고하면 한쪽은 오답 |
| `visibility:hidden`, `clip`·크기 0 잘라내기는 4기법이 아니라 **ETC**로 | 공모전 정의에 없어 TRANSPARENT/OFFSCREEN 어느 쪽인지 불확실. `result.json`에 넣으면 오탐 위험. 주최 측이 OFFSCREEN이라고 답하면 `ExtraDetectors`에서 옮기면 된다 |
| 선택자는 요소 + 부모부터 시작해 유일해질 때까지 위로 | 예시 표기와 같고, 짧을수록 채점 쪽 DOM과 어긋날 여지가 적다 |
| 같은 주소의 iframe이 여럿이면 `div.x > iframe[src="…"]:nth-of-type(2)` | `iframe[src="…"]`만으로는 두 곳을 가리킨다 |
| `/`와 `/index.html`은 한 번만 방문(먼저 만난 주소로 보고) | 같은 내용을 두 주소로 보고하면 한쪽은 오답 |
| iframe의 src 주소는 독립 페이지로 방문하지 않음(링크로 걸려 있을 때만 방문) | iframe 안 내용은 부모 페이지 + `>>>`로 보고하는 것이 공모전 표기 |
| 주제어 하나뿐인 숨은 글은 그 말이 글의 대부분일 때만 보고 | 숨겨진 메뉴의 "카지노업 현황" 같은 정상 글 보호 |
| 숫자 치환은 낱말 안쪽에 있을 때만 인정(`c4sino` ○, `baccara77` ×) | 끝에 붙은 숫자는 그냥 숫자인 경우가 많다 |
| 워커 기본값: 메모리·코어에 따라 1~3 | 워커당 브라우저 약 650MB. 평가 PC 사양 미확인 |
| 요청이 거부되면(HTTP 400·403·429·5xx) 간격을 늘리고 그 페이지는 맨 뒤에서 한 번 더 시도, 40번 연달아 실패하면 중단 | 실사이트에서 요청이 몰리자 400을 돌려준 사례 |
| 진입 페이지를 본 뒤의 쿠키를 다른 워커에 나눔 | 접속 확인 쿠키가 없으면 하위 페이지를 거부하는 사이트 |
| `meta.topic`은 `"TOPIC"`(공식 예시 그대로), `--topic`으로 바꿀 수 있음 | 표에는 "TOPIC(불법광고)"로 적혀 있어 주최 측 확인 필요 |

## 4. 실사이트에서 나온 문제와 고친 것

| 사례 | 고친 것 |
|---|---|
| 진입 페이지가 스크립트로 한 번 더 이동해 점검 중이던 문서가 사라짐 | 새 문서가 뜰 때까지 기다렸다가 다시 점검(최대 4번 따라감) |
| 두 번째 워커의 요청이 전부 HTTP 400 | 진입 방문 뒤의 쿠키 공유, 실패 뒤 간격, 거부된 페이지 재시도 |
| 진입 페이지에서 38초 멈춤 | 감시 스레드가 끊고 다시 시도해 회복. 문서가 뜨지 않는 iframe은 2초 기다린 뒤 건너뛰게 함 |

점검 기록은 `docs/runs/`에 있고 저장소에 올리지 않는다.
